# DAX v1.0.12 — Mode Stability and Reflection Hardening

**DAX v1.0.12** is a stabilization release focused on making the new workstation behavior honest, provider-neutral, and robust enough to trust in day-to-day operator use. It finishes the reflection, mode, and control-surface work that had already landed on `main` and turns it into a cleaner stable release.

## Highlights

- **Truthful Agent Modes**: `plan`, `explore`, `docs`, and `audit` now present their real authority and constraints instead of drifting into each other’s behavior.
- **Provider-Neutral Reflection**: Reflection policy is now taught in the shared session prompt path, so the feature no longer depends on one prompt family to behave well.
- **Real Operator Controls**: Session header `DISPLAY_MODE` and `QUEUE` controls now affect actual UI behavior rather than flipping dead settings.
- **Safer Verification Commands**: The shell verification allowlist now matches the safe command shapes DAX actually needs in release work, including `python -m pytest`, `go test ./...`, and `npm/pnpm exec vitest run`.

## Why This Release Matters

The previous release line made DAX calmer and more polished around planning, status surfaces, and the end-of-session handoff. `v1.0.12` makes the newer workstation work more trustworthy:

- visible controls now do something real
- mode prompts stop overpromising
- reflection behaves consistently across provider paths
- safe verification commands are hardened without blocking normal release checks

## Validation

- `bun run release:verify`
- `bun run --cwd packages/dax src/index.ts --help`
- Live Codex smoke runs for `plan`, `explore`, `docs`, `audit`, and `build`
- GitHub Actions CI on `main`

## Operator Outcome

This release should feel more stable and less gimmicky. DAX now behaves more consistently across modes, surfaces reflection more honestly, and gives operators controls they can trust instead of decorative toggles.
