# DAX v1.0.4 — Subscription Flow Hardening & Docs Consolidation

**DAX (Deterministic AI Execution)** v1.0.4 turns the last release-candidate fixes into a clean public artifact. This release hardens the Gemini subscription path, fixes `dax run` completion behavior, and adds a much more complete user manual for both developers and non-developers.

---

## What's New

### Cleaner Gemini Subscription UX

The Google / Gemini flow now centers on three clearer user-facing lanes:

| Option | Best For |
| --- | --- |
| **Gemini API Key** | Google AI Studio and pay-as-you-go usage |
| **Gemini Subscription Sign-In** | Gemini Pro / Pro Plus / local `gemini` CLI users |
| **Custom Google OAuth Client** | Advanced or team-managed OAuth setups |

`Gemini Subscription Sign-In` now behaves more like a real operator-facing lane and less like a loose collection of Google auth edge cases.

### Better Subscription Error Handling

- expired imported Gemini CLI sessions now tell users to run `gemini` again
- subscription-lane rate limit messaging is clearer and less misleading
- DAX now cools down more gracefully instead of hammering the same hot lane

### `dax run` Finishes Cleanly

`dax run` now exits cleanly after a successful terminal response instead of lingering after the result has already been emitted.

### Stronger Public Documentation

This release also consolidates the docs into a clearer learning path with new public-facing guides:

- `User Guide`
- `Prompt Engineering and Intent Guide`
- `Tool Reference and Risk Matrix`
- `Project Memory Guide`
- `Policy Customization and RAO Tuning`
- `Builder's Note`

The docs are now better aligned for:

- developers
- non-developers
- operators
- curious builders evaluating DAX for real use

---

## Fixed

- unified Google auth choices across CLI and TUI
- removed misleading custom OAuth guidance from the Gemini CLI import path
- improved local-machine auth scope explanation in the docs
- improved release-surface readability and cross-linking
