# DAX v1.2.0-beta.1

`v1.2.0-beta.1` is the first public proof of DAX's "bring your own agent, keep your governance" direction. Claude Code, Codex CLI, and Gemini CLI can act as replaceable workers, while DAX remains the authority for scope, verification, evidence, and human approval.

## What to validate

```bash
dax doctor
dax worker run codex --write-scope "src/**" --forbid package.json --verify "bun test" -- \
  "make one bounded change with tests"
```

Before creating the run, DAX shows a veto card with the exact constraints and their provenance. During execution it reports phase changes. A worker-produced patch reaches review only after DAX computes the diff, enforces path scope, and runs every declared verification command.

## Trust boundary

- macOS workers require a successful Seatbelt probe.
- Linux workers require bubblewrap and a successful probe.
- Windows workers fail closed in this beta.
- Worker writes are confined to the disposable checkout; host reads remain possible.
- Worker execution has provider network access; verification has no network.
- Persisted verification previews are redacted, while receipts attest the original result digest.

This is a beta because the new execution boundary needs real-repository use and cross-platform receipts before it deserves a stable label. DAX's built-in execution paths remain available when the external-worker lane is unavailable.

## Other hardening

- Provider doctor checks now reflect configured lanes instead of failing on unused providers.
- Concurrent project-memory initialization no longer flakes on SQLite WAL recovery.
- Release packaging installs the exact cross-platform native dependencies it builds.
- Flowright capability receipts and RunLedger evidence export make the suite boundary concrete without giving DAX ownership of workflow truth.

## Release evidence

The release PR must pass the GitHub CI matrix on Ubuntu, macOS, and Windows. The final release record should include:

- TypeScript typecheck, lint, tests, and smoke evals
- Rust format, clippy, and workspace tests
- repository-integrity and legacy-root guards
- canonical 11-target release build with manifest and checksums
- dependency audit with zero high-severity findings
